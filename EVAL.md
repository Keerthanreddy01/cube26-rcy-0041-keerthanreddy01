## 2. Evaluation Methodology & Independent Ground Truth

### Ground Truth Definition
To ensure rigorous evaluation, ground truth was **not** generated by the decision engine itself. Instead, an independent evaluation fixture ([`src/lib/eval-fixture.ts`](src/lib/eval-fixture.ts)) was established by auditing the raw evidence records in `data/upstream/`:

1. **`fulfilment_fee_weight_tier` (42 cases)**: Expected `NO_CLAIM`. Standard fulfillment fee; upstream operational logs do not record scale calibration errors.
2. **`inbound_defect_fee` (9 cases)**:
   - If receiving records show pre-existing damage (`unit_damage !== 'none'`), the defect fee is considered justified by dock intake condition → Expected `NO_CLAIM`.
   - If receiving or prep has uncertain inspection flags (`uncertain`), human inspection is required → Expected `REVIEW_REQUIRED`.
   - If receiving confirms clean arrival and prep confirms all work order checks passed → Expected `CLAIM_RECOMMENDED`.
3. **`lost_inbound` (5 cases)**:
   - If receiving confirms item was received with undamaged carton/unit → Expected `CLAIM_RECOMMENDED`.
   - If receiving record notes crushed carton or uncertain condition → Expected `REVIEW_REQUIRED`.
4. **`damaged_in_warehouse` (1 case)**:
   - If receiving confirms clean undamaged arrival → Expected `CLAIM_RECOMMENDED`.
5. **`refund_issued_item_not_returned` (4 cases)**:
   - If returns center record confirms item was received and dispositioned → Expected `CLAIM_RECOMMENDED`.

### Independent Ground Truth Distribution (61 Cases)
- `NO_CLAIM`: **43**
- `REVIEW_REQUIRED`: **4**
- `CLAIM_RECOMMENDED`: **14**

## 3. How Precision is Calculated

$$\text{Claim Precision} = \frac{\text{Correctly Supported Claims}}{\text{All Claims Recommended}}$$

In accordance with buildathon rules, the denominator includes **all** claims recommended by the engine, not an arbitrary accuracy score.

$$\text{Claim Precision} = \frac{14}{14} = 100.0\%$$

### Cross-Stage Reasoning & Causal Precedence: Case `FEE-0095-1`
- **Charge**: Inbound defect fee of $0.50 on `UNIT-0095`.
- **Upstream Evidence**:
  - Receiving (Stage 1): Logged `unit_damage=water` and `carton_damage=crushing`.
  - Prep (Stage 2): Logged compliant packaging (polybag present, FNSKU flat, barcode covered).
- **Core Reasoning Principle**:
  *"Later packaging compliance does not establish that the unit was free from pre-existing receiving damage."*
- **Decision Engine Output**: `NO_CLAIM` (Inbound defect fee justified by pre-existing water damage recorded at intake).
- **Independent Ground Truth**: `NO_CLAIM`.
- **Result**: Exactly matches ground truth without any charge-specific hardcoding. The engine enforces generalized cross-stage causality across all charges.

## 6. Known Limitations

1. **Synthetic Data Nature**: Results are derived from the organizer-provided synthetic dataset where requirements flags are sample fixtures.
2. **Parcel Scale Calibrations**: The dataset contains no weight scale calibration logs; standard weight tier fulfillment fees (`fulfilment_fee_weight_tier`) are treated as non-recoverable by default.
3. **No Direct Amazon Submission**: All claims are generated in `DRAFT CLAIM` / `READY FOR SUBMISSION` status for seller audit. No direct SP-API or Seller Central submission is fabricated.
